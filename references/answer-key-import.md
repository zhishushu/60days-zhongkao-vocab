# 把《答案册》导成真题大作战题库

适用：词册只写「答案见《答案册》P67」，用户另外给了一份答案册 PDF，要求「和答案一样才算对」并且带解析。产出是 `assets/exercises-答案册.json`（`{d,no,s,h,ans,note}`），由 `scripts/import_answers.py` 生成。

## 0. 先判有没有文字层

```python
import pymupdf; d = pymupdf.open(pdf); d[0].get_text()  # 空串 = 扫描版
```

扫描版才走 `ocr_pdf.py`（答案册通常只有 5~10 页，200 DPI 约 1 分钟）。已有词册 OCR 结果可直接复用，不要重跑 106 页。

## 1. 词册 → 每 Day 的编号句子

- **Day 归属不要信 OCR 的页眉**：`Day 3` / `Day 9` 这类页头常常识别不出来，还有 `Day 300`（实为 Day 30）、`KDay 12`。用「页面 token 与该 Day 词表的重合数」定页面→Day，或先用已知对齐页推算固定偏移（本套书 `p004 = Day 1`，即 `pN → Day N-3`）。
- 题目在每页底部「即时小练」之后，形如 `1.What about` + 同行右侧 `( go) to Zhongshan Park…`。
- **空格位置 = 同一视觉行里相邻识别框的横向间隙 > 55px**（原书的填空下划线不是字符）。只按文本拼接会丢掉空格，句子看起来是完整的。
- 首字母题（`Lucy was a____ from school`）在 OCR 里就是「一个字母 + 间隙 + 后半句」，同上处理。

## 2. 答案册 → 每 Day 的编号答案

- 版面是**两栏流式**：阅读顺序 = 左栏自上而下，再右栏自上而下；一个 Day 的列表可能被页/栏切开（左栏末尾 `1..7`，右栏顶部接着 `8..`）。
- 每段以 `Day N 即时小练` 开头，后接 `1.xxx 2.xxx`；带解析的条目是 `3.take【解析】空处位于…`，解析换行后**没有编号**，要接到上一条的 note 上。
- **遇到「第二部分」必须停**：那是词汇运用/单项选择等别的题型。不停的话最后一个 Day 会吞下 76~128 条，总题数从 ~340 虚增到 540。
- OCR 会把连着的编号粘成 `6.to practice7.to take`：匹配编号前先在「字母后紧跟的数字」处补空格。

## 3. 配对：按题号，不要按顺序做序列对齐

两边都有题号，且题号本来就对应。**不要**用「提示词相似度 + DP 序列对齐」去猜——实测会把整个 Day 的答案整体错位一位（Day 13 的 `(create)` 分到 `to stay`），而且错得很安静。做法：

```python
items = {it['no']: it for it in ex_map[day]}
for no, ans, note in answers[day]:
    it = items.pop(no, None)   # 取不到就记进 miss，不猜
```

## 4. 用「提示词 ↔ 答案」校验对齐

即使按题号配完也要验一遍：每条句子里的英文括号提示词，答案必须是它的词形（含不规则：`good→better`、`high→height`、`wake→woke`、`throw→threw`、`think→thoughts`、`die→death`、`safe→safety`）。不一致就是印重了题号。

真实案例：某 Day 的答案列表出现 `5. 6. 5. 6.`（同一 Day 印了两个题号系列），靠语义逐题校正成 `up / thankful / thoughts`，并把这种例外写进脚本的 `DAY_FIX` 常量，别只改数据文件——否则下次重导又错回去。

## 5. 清洗（全部都要做，少一条就会出现在学生眼前）

- `as 1 long as`（`I` 被 OCR 成 `1`）、行首 `1 am` → `I am`、`1` 紧贴 `____` 时直接删掉
- `hhabit` → `habit`（首字母重复）
- 行尾页码：`…all their lives, 10` → 去掉孤立数字
- 空格：`me____` → `me ____`（字母数 ≥2 时补空格），`a(n)____` → `a(n) ____`；`____ (` 归一成 `____ (`
- 结尾补句号；`？，` 转半角；`,.` / `,,` 归一

## 6. 丢掉的题要报数

扫描件边缘被切掉的句子（`Please c`、`The population`、`…to make us 1`）没有空也没有完整词，只能丢。典型是 341 条里丢 7 条。**交付时把「实际多少题 / 丢了哪几条」讲清楚**，别让用户以为答案册 100% 覆盖。

## 7. 产出与校验

```bash
"$PY" scripts/import_answers.py --words-ocr <词册OCR> --answers-ocr <答案册OCR> \
     --out assets/exercises-答案册.json
```

自检四问：每题都有 `ans`？`s` 里都有 `____`？`h` 覆盖多少（英文提示词 + 首字母拆分合理）？`note` 条数是否与答案册里 `【解析】` 的数量量级相符？

## 显示层配套（模板已做，改前端别弄丢）

- 填答案展示要用 `([A-Za-z])?_{2,}` 替换：首字母题原句是 `N____`，只替换下划线会渲染成 `NNothing`。
- 有 `h` 显示「提示词：able（用它的正确形式填空）」；没有 `h` 但句子里有首字母，显示「提示词：a（首字母提示，填完整单词）」。首字母检测要求该字母**前后都不是字母**（`(?<![A-Za-z])([A-Za-z])\s*_{2,}`），否则 `the ____` 会误报提示词 `e`。
- 结果页、错题本都要带 `Day N · 第 K 题` 和 `解析：<note>`。
